# Котокликер для Android

Нативная версия игры на Kotlin и Jetpack Compose. Работает полностью без интернета и без разрешений. Она задумана в
первую очередь для пожилого игрока: крупные элементы, спокойные мини-игры без таймера, надёжное автосохранение.
Веб-версия в корне репозитория остаётся как есть; правила и баланс здесь портированы с неё и проверены на совпадение.

## Устройство

Два Gradle-модуля:

| Модуль | Что внутри |
|---|---|
| `game` | Чистый Kotlin (JVM), без Android. Данные (комнаты, коты, улучшения), экономика и редьюсер `GameEngine`, четыре мини-игры, сохранение, `GameSession` (живая игра, оффлайн-доход). Тесты идут за секунды без эмулятора. |
| `app` | Android: `MainActivity`, `GameViewModel`, экраны на Compose (`ui/`), реестр картинок. |

Главные идеи:

* **Одно состояние, один редьюсер.** `GameState` неизменяемый, меняется только через `GameEngine.reduce(state, action)`.
  Так же устроена веб-версия, поэтому порт почти дословный.
* **Сохранение** (`game/save`): один JSON-файл `files/save/save.json`. Запись идёт через `save.json.tmp` и резервную
  копию `save.bak`, при чтении берётся самый свежий читаемый файл. Загрузка ничему не доверяет: лишнее отбрасывается,
  числа ограничиваются. Активный раунд мини-игры сохраняется вместе со всей игрой.
* **Время.** Пока игра на экране, время идёт по монотонным часам. Всё время «вне экрана» (свёрнуто, убит процесс,
  поворот) засчитывается как оффлайн-доход (не больше 8 часов) ровно один раз: на старте и при возврате.
* **Поворот и сворачивание.** `ViewModel` переживает поворот. Портрет использует «мобильную» раскладку мебели,
  ландшафт и планшет «десктопную» (как в веб-версии).
* **Сброс прогресса и режим «Эксперт»** требуют двух подтверждений (`WipeConfirmDialogs`); кнопка сброса находится
  на экране «Настройки», а не в основном интерфейсе.

## Проверка на совпадение с веб-версией

`tools/android/export_engine_golden.mjs` прогоняет веб-редьюсер (TypeScript из `src/game`) по сценариям и пишет
состояния в `game/src/test/resources/golden/engine.json`. `EngineParityTest` повторяет те же шаги на Kotlin и сравнивает
состояние. Есть сценарии для экономики, каждой из четырёх мини-игр (включая случайные партии) и «Эксперта».
`DataParityTest` сверяет таблицы данных (`data.json`, скрипт `export_golden.mjs`).

Обновить записи (нужен Node и `npm install` в корне репозитория):

```bash
node tools/android/export_golden.mjs
node tools/android/export_engine_golden.mjs
```

Если правила веб-версии меняются, эти команды показывают, что нужно поправить в Kotlin.

## Сборка и запуск

Открыть **папку `android`** (не корень репозитория) в Android Studio, дождаться Sync.

* Тесты: правый клик по модулю `game` → *Run Tests*.
* Запуск на телефоне или эмуляторе: конфигурация `app`. В отладочной сборке в «Настройках» есть раздел
  «Для проверки» (добавить рыбок, купить всё в комнате); в релизной сборке его нет.

**Важно для Windows:** если имя пользователя содержит не-ASCII буквы, держите проект и `GRADLE_USER_HOME` в пути без
них (например `C:\dev\...`), иначе тестовые процессы Gradle не стартуют. Заодно можно задать ASCII-папку временных
файлов в `~/.gradle/gradle.properties`: `org.gradle.jvmargs=... -Djava.io.tmpdir=C:/dev/tmp`.

## Картинки

Исходные PNG лежат в `public/assets` (общие с веб-версией). Для Android они переводятся в WebP скриптом
`tools/android/convert_assets.py` (нужен Python и Pillow) и сохраняются в `app/src/main/res/drawable-nodpi`.
Имена ресурсов строятся по правилам из шапки скрипта; `AssetRegistry` находит их по имени, а `res/raw/keep.xml` не
даёт сборке их удалить. Иконка приложения генерируется `tools/android/make_launcher_icon.py`.

## Релизная сборка для установки на телефон

Android Studio → *Build → Generate Signed App Bundle or APK → APK*. При первом запуске создайте хранилище ключей
(*Create new…*) и **сохраните файл и пароли в надёжном месте**: обновления приложения должны быть подписаны тем же ключом,
иначе телефон потребует удалить старую версию вместе с прогрессом. Ключ и пароли в репозиторий не кладут.

Готовый APK лежит в `app/release/`. Его можно отправить на телефон файлом и установить (разрешив установку из
неизвестных источников). Прогресс хранится в приватной папке приложения и при обновлении сохраняется; автоматическое
резервное копирование Android (`allowBackup`) включено для папки `save/`.
