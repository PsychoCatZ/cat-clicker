# Котокликер — контекст для агентов и разделение территорий

Игра про котов и комнаты (клики, рыбки, улучшения, четыре спокойные мини-игры). Репозиторий один
(`github.com/PsychoCatZ/cat-clicker`), но в нём **две версии игры, которые ведут разные агенты**.
Общение с владельцем — по-русски, кратко. Не выдумывать: сначала проверять командой.

## Территории (главное правило)

| Часть | Что это | Кто ведёт | Где лежит |
|---|---|---|---|
| **Браузерная версия** | Vite + React + TypeScript | **Codex** | всё, кроме `android/` и `tools/android/` |
| **Android-порт** | Kotlin + Jetpack Compose | **Claude Code** | `android/` и `tools/android/` |

Граница проходит **по папкам, а не по веткам**: обе версии живут в одной ветке `main`
(ветка `android-port` смержена в `main` через PR #1 от 2026-09-22 и больше не используется).

Определите, кто вы, и держитесь своей территории:

- **Если вы Claude Code:** правьте **только** `android/` и `tools/android/`.
  **Не изменяйте** браузерную версию: `src/`, `index.html`, `vite.config.ts`, `tsconfig*.json`,
  `package.json`, `package-lock.json`, `tools/*.mjs`, `tools/*.py` (кроме `tools/android/`), корневой
  `README.md` и корневые PNG-листы. Веб-код вам нужен как **эталон для чтения** (правила и баланс), а
  не как объект правки. Если в вебе найден баг или нужна правка — опишите её владельцу, не чините.
- **Если вы Codex:** правьте браузерную версию (всё, что вне `android/` и `tools/android/`).
  **Не изменяйте** `android/` и `tools/android/`.
- **Если вы любой другой агент:** сначала спросите владельца, какую версию вы ведёте.

Перед каждым коммитом смотрите `git status` / `git diff --stat`: в коммит должны попадать только файлы
вашей территории. Перед пушем — `git pull --rebase origin main` (второй агент мог запушить раньше).
Не создавайте из-за этого отдельных веток «для порядка» без просьбы владельца.

Общие файлы, которые не принадлежат ни одной стороне, меняет только владелец или по его прямой просьбе:
`AGENTS.md`, `CLAUDE.md`, `.gitignore`, `.gitattributes`.

## Как версии связаны (где границы протекают)

Android не независим от веба: он портирует его правила и проверяется на совпадение с ним.

- **Эталон правил — веб.** `src/game/*` (данные, экономика, редьюсер, мини-игры). Android повторяет их
  в `android/game` (чистый Kotlin) и сверяется «золотыми» прогонами: `tools/android/export_engine_golden.mjs`
  и `export_golden.mjs` запускают веб-редьюсер и пишут эталонные состояния, `EngineParityTest` /
  `DataParityTest` сравнивают их с Kotlin (подробности — `android/README.md`).
- **Картинки общие.** Источник — `public/assets/`; Android конвертирует их в WebP скриптом
  `tools/android/convert_assets.py`. Переименование или удаление файлов в `public/assets/` ломает Android.
- **Порядок при изменении веба (для Codex):** если меняете правила, баланс, данные или имена ассетов в
  `src/game` / `public/assets`, укажите в сообщении коммита `[affects android]` и коротко — что именно.
  Это сигнал Claude Code, что нужно пересчитать эталоны и поправить Kotlin.
- **Порядок в Android (для Claude Code):** перед работой сделайте `git pull --rebase origin main`,
  затем запустите оба скрипта эталонов (нужны Node и `npm install` в корне) и посмотрите, не разошлись ли
  тесты паритета (`git log` с пометкой `[affects android]` подскажет, что менялось); расхождение чините
  в Kotlin, а не в вебе.

## Браузерная версия (территория Codex)

Стек: React 19, TypeScript 5.9, Vite 7. Состояние — один редьюсер; прогресс в `localStorage`.

```bash
npm install
npm run dev          # разработка
npm run build        # tsc -b && vite build
npm run check        # проверки логики: game, match3, pairs, mahjong, sliding
```

Структура: `src/game/` — данные, экономика и чистая логика мини-игр; `src/components/` — интерфейс;
`public/assets/` — нарезанные картинки; `tools/` — нарезчик исходных листов (`slice_assets.py`) и проверки
игровых правил. Корневые `*.png` — исходные листы для нарезки, не трогать. Правила игры описаны в `README.md`.
Перед сдачей должен проходить `npm run build` и `npm run check`.

## Android-порт (территория Claude Code)

Два Gradle-модуля: `game` (чистый Kotlin, без Android: данные, экономика `GameEngine`, мини-игры, сохранение)
и `app` (Compose-интерфейс). Подробно — `android/README.md`; прочитайте его перед работой.

- Открывать в Android Studio папку **`android`**, не корень репозитория.
- Логику сначала делайте в `game` и проверяйте тестами (`EngineParityTest`, `DataParityTest` и др.), затем
  подключайте в `app`. Состояние неизменяемое, меняется только через `GameEngine.reduce`.
- Сохранение — один JSON с временным файлом и резервной копией; не менять формат без миграции: у
  игрока (пожилой человек) должен сохраняться прогресс при обновлении приложения.
- Целевой игрок — пожилой: крупные элементы, без таймеров и спешки; в релизной сборке нет отладочного раздела.
- **Windows:** имя пользователя с кириллицей ломает тестовые процессы Gradle. Держите `GRADLE_USER_HOME` и
  временные файлы в ASCII-пути (например `C:\dev\...`), см. `android/README.md`.
- **Секреты:** хранилище ключей подписи (`*.jks`, `*.keystore`) и пароли в репозиторий не кладём (они в
  `.gitignore`). Потеря ключа = невозможно обновить приложение на телефонах поверх старой версии.
  Подписанный `android/app/release/app-release.apk` лежит в git намеренно.

## Прочее

- Проект скопирован со старой системы Windows; права на файлы исправлены (владелец — `HOME-PC\Кот`).
- Есть отдельный ранний Kotlin-эксперимент `D:\Dev\CatClicker` (репозиторий `KotoKliker-The-Path-to-Kotification`);
  он не связан с этим проектом и является архивом.
- Коммиты и пуш делайте после проверки, в стиле уже существующей истории (`feat:` / `Android: …`).
